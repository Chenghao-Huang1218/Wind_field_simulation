## 运行方式

用户希望显式激活 Conda 环境。两个终端分别执行，保持终端一运行后再启动终端二。

终端一：

```bash
source /home/raids/miniconda3/etc/profile.d/conda.sh
conda activate env_uav
cd /home/raids/Wind_field_simulation
bash scripts/run_px4_sitl.sh
```

终端二：

```bash
source /home/raids/miniconda3/etc/profile.d/conda.sh
conda activate env_uav
cd /home/raids/Wind_field_simulation
python scripts/run_simulation.py
```

默认模拟器 TCP 端口为 4560，Offboard UDP 端口为 14580。启动器设置 `PX4_SIM_MODEL=none_iris` 和 `PX4_SIM_FLOAT_STATE=1`。

参考环境：Python 3.12、MuJoCo 3.6.0、NumPy 2.4.4、PyTorch 2.11.0（原环境 CUDA 构建为 `+cu128`）、Matplotlib 3.10.9。通用 Python 库、Conda 环境、系统动态库与编译工具链没有复制到新项目。

启动时没有已配置的风扰参数，X、Y 两个输入框为空，`Wind ON/OFF` 禁用，显示 `Wind not configured.`。面板右下方填写完整 XY 水平风速并点击 `Apply Wind`，通过命令队列在仿真循环中整体接受后，开关才解除禁用；此时仍为 OFF，须点击开关才施加风扰。开启后仍可实时修改参数。命令行 `--wind-x/y` 只预填草稿，不能绕过 Apply；没有显式参数时 `SimulationConfig.wind_velocity_world=None`，显式预填的缺省水平分量为 0。Z 风速固定为 0，已移除 `--wind-z`；内部仍使用 `[X,Y,0]` 三维向量，通用校验拒绝非零 Z 风速；PINN 原始三轴预测保留，但实际施加的风扰力只取 XY 分量。一般操作顺序是等待 PX4 连接、Unlock 并等待确认、Takeoff，再选择轨迹或配置并开启风扰。`--no-viewer` 仅关闭 MuJoCo 三维窗口，仍保留 Matplotlib 面板。

输入空值、非数字、非有限数、非零 Z 或水平合风速超过 3 m/s 会拒绝并保留上一组设置；首次失败保持未配置。仍保留旧 float32 数值保护，但应用物理风域已收紧为合模长 ≤3 m/s。全零配置有效；关闭风扰保留参数；编辑刷新不覆盖草稿，接受参数不更改开关/目标或重置 XY EMA。面板保持 7.4 × 5.0 英寸，状态新增后端名称和仿真时间。命令行仍只是待 Apply 的草稿。

## 模型和风扰实现

主场景为：

```text
src/wind_field_simulation/assets/scenes/default/robot_quadrotor_950_with_arm.xml
```

其引用资源均在本项目 `src/wind_field_simulation/assets/robot_models/` 下，包括 X4-950、Airbot Play、地面、柜子、网格及纹理。模型资源是独立副本，已核对不是旧项目的符号链接或共享文件；修改它们不会修改旧项目模型。不要把默认 XML 或资源引用改回旧工程路径。

默认场景现只加载无人机、机械臂、地面及光照；已移除两个圆柱、长方体物块和柜子引用。柜子资源文件仍保留，但默认场景不使用。

参数位于 `assets/configs/X4-950.params`；两份权重为 `assets/checkpoints/best_model.pt` 和 `normalizer.pt`，以上 `assets/` 均相对 Python 包目录。

当前风扰路径是 `ConstantWindField` → 所选解析/旧 PINN 后端的原始三轴加速度 → XY 投影 → 原 EMA/限幅 → 乘整机质量 → 原根 body 单点水平 force-only。解析返回同状态有风减无风的完整 `delta_F/m_total`，不另施无风阻力或力矩。原始 Z 诊断保留，实际风力 Z 精确为零。`last_pinn_force` 名称为兼容保留，现在也可表示解析后端实际风力。仅旧 PINN 使用 Hummingbird 输入兼容参数。解析冻结几何、经验 Cd/密度及未验证边界见参考报告；不称为实测标定或 CFD。

修复依据：用户报告水平风仍有 Z 扰动。全新进程中尚未 Apply 时无配置且施力为 0；Apply `[1,0,0]` 后，CPU PINN 原始 Z 残差约 `0.037781 m/s²`，旧实现首步会施加约 `0.015113 N` 垂直力，无需任何旧 `Z=1` 设置即可复现。原因是只限制了输入而保留了模型三轴施力。现修正为实际水平施力，PINN 权重及原始输出不变。

风场为空间均匀、两次手动更新之间恒定；更新命令替换 `ConstantWindField` 实例，不引入阵风或湍流模型。

## EXIT 联动修复

用户曾报告点击 EXIT 后，仿真退出而终端一中的 PX4 仍在运行。原逻辑只发送 MAVLink 关机请求；复制的 PX4 Commander 中该关机分支受硬件电源控制编译条件限制。

现实现：

1. 终端一的 Python 启动器创建并持有唯一 SITL 子进程，在 `outputs/px4/` 中维护文件锁和会话记录。
2. EXIT 原有逻辑仍停止转子、发送上锁和关机请求；图形和传输清理后，`main()` 再写入当前会话的本地退出请求。
3. 启动器只停止自己的子进程，先发 SIGINT；10 秒未退出则 SIGTERM，再等 5 秒后才强制结束同一个子进程。不会用记录中的 PID 去终止任意进程。
4. 旧会话请求无效；同一状态目录不允许重复启动器。

两个程序退出后，两个终端回到提示符，终端窗口保留。更新前已运行的旧 SITL 没有受管理会话，需手动停止一次并通过新版启动脚本重启。

默认状态目录为项目内的 `outputs/px4/`。若自定义 `PX4_STATE_DIR`，两个终端设置相同绝对路径。其他启动路径或安装位置需要核对该状态目录是否一致。
